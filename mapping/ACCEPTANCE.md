# M0 验收用例与交付要求

状态：设计预期，尚未运行。所有毫秒数是人为指定成本，不是 GPU 测量。

## 1. 共同条件

- W1、W2：FP32，GGML `ne=[4,4,1,1]`，每个 64 B，初始仅在 DRAM。
- x：FP32，`ne=[4,1,1,1]`，16 B，初始仅在 VRAM，已经计入预算。
- 所有中间/输出向量均为 16 B，初始无 allocation；仅最终 y 是请求输出。
- 每次权重 H2D 为 3 ms，每次 MUL_MAT 为 2 ms，RELU / ADD 各为 1 ms。
- workspace=0、runtime reserve=0、alignment=1 B。一次 compute、一次 copy；允许计算复制重叠。
- 允许显式 EVICT；只读权重可重载，x 和中间结果无备份，只能在所有消费者完成后释放。
- 规范存储单位为 ns，以下表格用 ms 方便手算。compute 操作不能重复执行。

M0 使用抽象容量，96 B 等数值只验证分配语义，不代表真实 CUDA 最小分配或 workspace。

## 2. 链式图：h=W1*x；y=W2*h

操作 ID 为 c1、c2；输出张量 ID 为 h、y。

### 容量 160 B：最优 8 ms

| 时间 | 动作/事件 | 显存说明 |
|---|---|---|
| 0 | 启动 W1 copy，持续到 3 | x16 + W1预留64 = 80 |
| 3 | W1就绪，启动 c1 至5；启动 W2 copy 至6 | x16 + W1 64 + h预留16 + W2预留64 = 160 |
| 5 | c1完成，显式释放 W1、x | h16 + W2预留64 = 80 |
| 6 | W2就绪，启动 c2 至8 | h16 + W2 64 + y预留16 = 96 |
| 8 | c2完成，y就绪，结束 | 峰值160；H2D 128 B |

下界：首次计算至少在3开始；两次必要复制共6 ms，c2只能在其权重与h均就绪后执行2 ms。复制顺序 W1→W2 达到8；反序也不可能更早。故8 ms为最优。

### 容量 96 B：最优 10 ms

W1 copy 0–3，c1 3–5；c1期间已用96，W2不能预取。5时释放W1和x，W2 copy 5–8，c2 8–10。峰值96，H2D 128 B。

### 容量 95 B：无解

c1至少同时需要 x16 + W1 64 + h输出16 = 96。M0无原地复用，不能腾掉输入来分配输出。

把容量160的动作序列写成不带指纹的人工mapping，scenario_id设为96 B目标场景后回放：3时试图启动W2复制必须报CAPACITY_EXCEEDED，不能暗中延迟复制到5。带旧指纹跨场景复用的测试另行检查身份不匹配，避免在此处先被指纹检查拦截。

## 3. 残差图：h=W1*x；a=relu(h)；b=W2*a；y=b+x

c1 / r / c2 / add 分别为2/1/2/1 ms。x必须一直保留到最终add完成。

| 容量 | 最优makespan | 一个达到最优的时序 |
|---|---|---|
| 160 B | 9 ms | W1 0–3；c1 3–5；W2 3–6；r 5–6；c2 6–8；add 8–9 |
| 112 B | 11 ms | W1 0–3；c1 3–5；W2 5–8；r 5–6；c2 8–10；add 10–11 |
| 111 B | infeasible | c2需要 x16 + a16 + W2 64 + b输出16 =112 |

在5时释放W1，在r完成后释放h，在c2完成后释放W2和a；x不得提前释放。112 B情况下，W2复制可与r重叠，峰值为 x+h+a+W2=112。

最优性：160 B时从首次W1加载起的必要依赖链为3+2+1+2+1=9；112 B时W2无法与c1驻留共存，最早5开始复制，c2最早8开始，因此至少11。

验证尝试在c1完成后EVICT(x)应报 LIVE_VALUE_LOSS；在c1运行中EVICT(x)应报 TENSOR_IN_USE。

## 4. 分叉图：a=W1*x；b=W2*x；y=a+b

c1、c2独立，但共享x；add同时需要a、b。

| 容量 | 最优makespan | 一个达到最优的时序 |
|---|---|---|
| 160 B | 9 ms | W1 0–3；c1 3–5；W2 3–6；c2 6–8；add 8–9 |
| 112 B | 11 ms | W1 0–3；c1 3–5；W2 5–8；c2 8–10；add 10–11 |
| 111 B | infeasible | 第二分支计算时必须同时保留x、首分支结果、第二权重与第二输出，共112 |

两分支先后互换也是合法最优方案；测试不能强制某一种顺序。

160 B下两次复制串行至少6 ms，最后一个分支随后计算至少2 ms，再add1 ms，故9最优。112 B下两个权重与输入无法同时驻留，第二复制至少在首分支完成的5时开始，故11最优。

先完成a后，不可释放x（b仍需要），也不可释放a（add仍需要）。不能把GGML节点遍历顺序误当作c1→c2的必需边。

## 5. 必须覆盖的语义用例

| 用例 | 预期 |
|---|---|
| 在copy完成前COMPUTE | INPUT_NOT_READY |
| 对READY或在途张量重复COPY | 拒绝，不重复分配 |
| 启动第二个同资源任务 | RESOURCE_BUSY |
| 开始动作后立即在另一个资源启动动作 | t不变，允许合法重叠 |
| 运行中释放输入或目标预留 | 拒绝，无容量回退 |
| 释放无备份且仍有未来消费者的中间结果 | LIVE_VALUE_LOSS |
| 对无副本张量再次EVICT | 拒绝空操作 |
| 无运行任务时ADVANCE | 拒绝，不能无限空等 |
| 两任务同刻完成 | 一次ADVANCE完成全部，再派发下一任务 |
| 同一输入在inputs中重复出现 | allocation不重复计数，读锁不泄漏 |
| 重复COMPUTE已经完成的操作 | 拒绝重计算 |
| EVICT最终输出 | 拒绝 |
| 最后一个消费者完成 | 可释放唯一GPU副本，空间变化正确 |
| weight被驱逐后再次需要 | 在有未启动消费者时可重载，正常计时间与字节 |
| workspace=16 B 的链式c1 | 容量95/96均不能启动c1；其执行至少需要112 B；完成后workspace释放 |
| alignment=32 B | 16 B向量按32 B分配，拷贝字节仍按有效storage_bytes |
| 初始x超过显存预算 | 搜索前报告initial_capacity_exceeded |
| view、非F32、原地共享存储、非连续输入 | unsupported，不计为普通独立张量 |
| GGML_OP_UNARY + GGML_UNARY_OP_RELU | 正确导出为semantic_op=RELU，并保留原始操作信息 |
| 未知输入/环/重复ID/多个生产者/缺成本 | invalid_input |
| 动作序列提前结束 | incomplete_mapping；不自动补完 |
| 成功后还有动作 | invalid_mapping，拒绝含糊终点 |

补充不依赖具体最优轨迹的性质：固定成本与动作空间不变时，增加显存容量不能使最优时间变差；限制为串行不能优于允许重叠的最优值。链式160 B禁用copy/compute重叠时应得到10 ms。

## 6. 搜索与结果身份

- 三种图的最优结果必须保存mapping，随后用model从初始状态回放；makespan、峰值、字节与事件应一致。
- 同一状态键的表示不应因集合/字典插入顺序改变；剩余时间或在途张量不同的状态不得错误合并。
- 不包含绝对t的去重，只适用于本版确定且无外部到达的模型；测试较晚到达的同未来状态不会替换较早者。
- 相同输入多次运行具有确定结果；对称图允许多个数学最优解，但同实现应稳定选取。
- 设置极小展开预算且未找到goal，结果应为unknown，不是infeasible。未确认最优的可行结果必须带optimality_proven=false。
- 只有取出最小代价goal或穷尽状态空间后，才能分别给出optimal或infeasible。
- 修改影响语义的scenario/workload后，带旧指纹mapping的回放应拒绝匹配；明确的无指纹人工mapping走完整语义校验。
- graph_origin=ggml只用于实际GGML导出；fixtures和合成成本均如实标记。
