# 开源库与预印本准备路线

更新：2026-10-17。本文记录发布边界和下一步交付，不代表已提交论文或已取得投稿资格保证。

## 当前可以发布什么

当前发布目标是 **0.1 alpha 研究库**：用 Python 描述模型、硬件与策略，将策略编译为动作，在同一执行状态、张量库存和资源账本中模拟。公开源码按根目录 [MIT 许可证](../LICENSE)提供。单独标注的第三方数据保留自己的许可证；例如[公开专家路由输入](../profiling/data/public-routes/README.md)使用 CC BY 4.0。

默认安装和教程应只依赖随包分发的代码及明确标为 synthetic 的小输入。用户可以提供自定义成本，也可以在目标硬件运行独立 profiling 工具。没有匹配成本或未知 workspace 时应明确拒绝或报告 unknown，不能静默套用本机 profile、按比例猜测或把未知值填零。

库的逻辑测试、合成时间线和硬件性能准确度是三类证据。当前完整性能质量门尚未通过；最新执行变换校准中的可接受预测数为 0。历史工具或某个单项指标的通过不能改写为全链路通过。当前发布可以证明代码与受限语义可检查，不能声称完整 LLM 已准确校准、全面复现已有系统或实际获得加速。

## 预印本需要补齐的内容

本机已有第七教学周策略空间稿件及 Word 草稿，其中 `XX` 是未完成实验，并不是可发布的最终结果。开源一个可用原型与形成一篇完成的研究论文是不同的交付。当前应先做以下闭环：

1. **冻结主张与能力表**：定义执行和存储调度的联合空间、合法性约束与动态策略的因果信息边界；逐项核对当前代码支持、显式拒绝和规划项。Python 接口模仿常用库的组织方式本身不是新贡献。
2. **表达与编译验证**：选小而代表性的 Dense/MoE、Attention/FFN 拆分与预载组合；独立手写预期动作、依赖、字节和生命周期，检查等价表达与错误拒绝。不能只用编译器自己的输出证明编译器正确。
3. **准确度校准**：冻结实现、精度、线程、设备和计时边界，分离 profile 拟合与留出运行；报告误差、未知覆盖、容量判断和可分辨策略对的排序。失败、OOM 和无法分辨的候选保留在分母中并说明状态。
4. **设计价值实验**：在相同候选预算下比较固定策略、只改执行、只改存储调度与联合选择；真实回放被选择的方案，报告相对最佳已测可行候选的 regret。若没有收益或无法可靠排序，就缩小结论。
5. **完成稿件**：用真实结果替换 `XX`，同步当前实现、图、公式、引用、作者贡献与限制；所有作者审阅同意。不能把计划中的结论改写成已观察结论。

没有必要等待所有未来功能完成才写文章，但应选择一个已经完成、证据充分的受限问题。尚未验证的硬件迁移、完整 P/D 服务、通用并行和统一内存能力不能因接口或元数据存在而写成实现成果。

## 公开版与匿名投稿版

截至上述日期，DAC 2027 明确允许 arXiv 预印本，同时要求投稿材料匿名，并要求 PDF 元数据去除作者身份。规则还要求提交的是完成稿，而非把关键证据留待后续的初稿。参见 [DAC 官方投稿规则](https://dac.com/2027/program/research-manuscript-submissions)。

可从同一源稿维护两个构建结果：

| 材料 | 处理方式 |
|---|---|
| 公开预印本 | 真实作者、单位和致谢，正常链接公开 GitHub；明确标注 preprint，尚未录用不得写 accepted。 |
| 匿名论文 PDF | 隐去作者、单位、身份性致谢和 PDF metadata；按规则用第三人称引用自己工作，避免链接暴露身份的个人仓库。 |
| 投稿系统表单 | 向组织方如实填写作者、单位、利益冲突，不因匿名 PDF 而省略。 |
| 可选评审代码 | 若系统允许代码附件或外链，制作匿名源码快照，去除 `.git` 历史、本机路径及身份信息；以当轮规则允许的渠道提供。 |

匿名代码快照是实践方案，不是此处替会议新增的强制格式。公开内容使身份可能被推断，双盲不保证绝对不可识别；需要认真处理提交材料，并在实际提交前复核当轮规则。不要为匿名而删除必要的第三方署名或伪造作者信息。

## arXiv 提交前准备

准备作者顺序与单位、题目/摘要、完整正文和参考文献、可重建源文件、图与编译后的 PDF、分类建议以及适用于**论文**的授权许可。代码的 MIT 许可证不等于论文的 arXiv 授权选择。先确认所有作者同意公开，再由有权限的作者在账户中提交；新分类投稿可能涉及 endorsement，是否需要由账户与分类状态决定。

官方入口：[提交流程](https://info.arxiv.org/help/submit/index.html)、[endorsement](https://info.arxiv.org/help/endorsement.html)、[论文许可](https://info.arxiv.org/help/license/index.html)。此轮只整理代码和准备路线，没有代为注册、申请 endorsement、上传或提交论文，也不承诺 arXiv 的处理时间或接收结果。

## 用于暑研申请的诚实表述

现在就可以在 CV/项目页给出源码地址、可安装版本、可运行示例和个人贡献。可写：

> 开发用于异构 LLM 推理策略表达、编译与离散事件模拟的开源研究原型；支持受限 Dense/MoE 执行与存储策略组合，正在进行独立硬件准确度验证。

根据个人实际贡献修改“开发”与职责，不把团队成果全部归为个人。README 演示、测试、方法说明与可复现实验脚本都是可展示成果；合成结果应标明 synthetic。尚未发布的文章列为 manuscript in preparation，拿到真实 arXiv 编号后再列为 preprint，只有真实投稿后才能写 submitted/under review，录用后才能写 accepted。论文是否足以投稿、是否录用和暑研结果均不能由开源状态保证。
