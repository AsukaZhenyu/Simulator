# 多模型、多设备验证的验收标准

这份文件在**测量之前**写定，测完不改。任何一条不满足，就在结果里写"不满足"，
不改判据、不改口径。

判据的阈值全部来自仓库里已有的合同，不是这次新定的：

| 来源 | 常量 |
|---|---|
| `profiling/dac_validation/e2a.py` | `QUALITY`：过程均值 APE ≤ 10%、试次均值 P90 APE ≤ 20%、过程内试次 CV ≤ 10%、观测器相对均值差 ≤ 5% |
| `profiling/model_swap/README.md` §4 | 成本表无 `null`、未知 workspace 不得当 0、不得跨形状复用价格 |
| `profiling/decision_margin/README.md` | 预测值必须能由坐标键逐位复算 |

## 1. 每个模型能支撑到哪一步

这决定了结果怎么写，不能混。三个 Qwen3 与两个 MoE 的结论强度**不一样**：

| 类别 | 模型 | 走哪条链路 | 能说的话 |
|---|---|---|---|
| Dense 全层 `full_causal` | Qwen3-0.6B / 1.7B / 4B | M2 的 `projection → attention → dense_ffn` 切片，逐形状实测成本 | 整模型在已实现切片上的预测误差 |
| MoE | granite-3.0-3b-a800m / Qwen1.5-MoE-A2.7B | 独立测量子图（`profiling/MOE_MEASUREMENT.md`） | **只能**说测量块抽象对 MoE FFN 的误差 |

**MoE 不能填 `.6` 整层成本表。** `m2-layer-0.6` 的 `costs.py` 只接受
`provenance="synthetic_layer"`，实测 MoE 成本没有可装载的边界。谁把 MoE 的实测
数字写进 `.6` 表，谁的"整层预测"就是假的。

**不能声称整模型级结论的**：任何含 `recurrent_linear` 或 `sliding_window` 层的
模型。Qwen3.5 系列（本地五个文件全是 `full_attention_interval=4` 的 hybrid）、
Granite-4.0-H-Tiny（40 层里 36 层 Mamba-2）、Trinity-Nano-Preview（2048 滑窗）
因此都不在这套验证里。理由不是"跑不动"，是**成本表没有那一项**。

## 2. 判据

### R1 字节身份

测量前 `fetch_models.py --check` 必须对每个模型报 `ok`。SHA-256 与大小都要对上
`models.json`。任何一条不符，该模型的结果作废，不是"近似可用"。

> 为什么：Q4_K_M 是同一名字下最容易被换掉的量。换过权重的模型几何相同、误差不同。

### R2 结构身份

`build_model.py --gguf` 从**本机这份文件**读出的 geometry 必须与 `models.json`
的 `geometry` 逐字段相等：`block_count`、`hidden_size`、`intermediate_size`、
`heads`、`kv_heads`、`head_dim`、`experts`、`top_k`。不等就停下，不要继续测。

### R3 价格属于设备

每个价格条目都带 `device` 字段（设备 id）。不同设备的条目**不许合并统计**，
也不许把一台机器的价格搬到另一台的报告里。`devices/<id>.json` 是唯一允许
跨设备比较的对象，它只有结构性事实（核数、内存、互联），没有价格。

### R4 不跨形状插值

成本表的键是 `(kind, device, phase, batch, tokens, visible_history)`。新形状
重新测，不许按线性或按比例从邻近形状推。缺条目就是 `null`（执行时会被拒），
不是 0。

### R5 稳定性闸门

每个键至少 20 个试次；过程内 CV > 10% 的条目自动降级为 `validation_only`，
不进主结果。降级条目要在报告里单独列出数量，不能只说"平均值"。

### R6 过程均值 APE ≤ 10%

按**每次重复各自打分**再平均，不是先平均再打分。两者在方差大时会给出不同
结论，口径固定为前者。

### R7 试次均值 P90 APE ≤ 20%

单次调用的分布尾部也要在界内。只报均值会藏掉长尾。

### R8 观测器相对均值差 ≤ 5%

外部观测（wall clock）与内部计时（CUDA event / `QueryThreadCycleTime`）之差。
超过 5% 时先说清是哪一个口径在报数，不要混用两种仪器的数字做分解。

### R9 MoE 边界

MoE 结果只能以"测量块 FFN 子图"的形式报告。路由轨迹必须来自**同一次**
被计时的那次调用（`ffn_moe_topk` 是跨步 VIEW，线性读会得到假的均匀路由）。
`moe_measured.py` 是现有唯一合法的封装。

### R10 预测可复算

`predictions.json` 里每条动作的坐标键按成本表求和，必须**逐位等于**存储的
`duration_ns`。残差不为 0 说明缓存或路径出了错，先修再报。

### R11 预注册

每个（模型，工作负载）的预测值在测量目标时延**之前**写入
`results/<campaign>/predicted.json`，带文件时间戳与设备 id。事后改预测等于
没预测。

### R12 失败保留在分母里

跑崩的进程、超时的试次都要留在记录里。`e2a.py` 的 `SEQUENCES` 与"每个失败
进程都保留"是既有做法，新战役沿用。

## 3. 预注册的预期（测之前写，测完对照）

这三条是可被证伪的，不是结论：

- **P1** 三个 dense 模型的误差不会随参数量单调上升。理由：抽象以"逐形状实测
  成本"为单位，模型规模只改变形状，不改变合同。**若出现单调趋势，说明缺少某个
  规模相关的项（例如内存带宽层次），要当成缺陷报，不要解释成"大模型更难"**。
- **P2** MoE 的误差大于 dense。理由：路由是数据相关的，测量块把专家选择藏进了
  一个不透明的宏任务。
- **P3** 同一模型换设备后，绝对价格变、**策略序**大致不变，但决策裕度会变。
  这与 `decision_margin` 的边界一致（裕度属于机器）。若出现跨设备的序翻转，
  那是比误差更有价值的发现，要单独写。

## 4. 不许写的

- 不许把三个 dense 模型说成"验证了模型族"——它们是同一族、同一分词器、同一
  量化档，只差规模。
- 不许把 MoE 子图误差说成整层或整模型误差。
- 不许用 hybrid 模型的代表层误差推断整模型。
- 不许在新的设备上复用笔记本的价格后声称"预测了那台机器"。
- 不许把 `--allow-unstable` 产出的条目混进平均值。
